# הצעה לאינטראקציות ברגרסיה של מהלכי קטאן

הצעה זו אינה משנה את שני המודלים שנבדקים בניסוי `frozen-linear-v3-vs-v4-200-v1`. מטרתה לבחור מספר קטן של מאפיינים נגזרים לניסוי עתידי, ללא שינוי בדאטה או אימון נוסף בזמן ההשוואה.

רגרסיית הפעולות הנוכחית היא סכום משוקלל של מאפיינים. מאפיין שהוא קבוע לכל המהלכים באותו מצב, למשל כמות המשאבים ביד או המרחק לניצחון, מוסיף אותו סכום לציון של כל מועמד ולכן אינו משנה ישירות את סדרם. הוא עדיין יכול לתרום לחיזוי ערך המצב וליעדי האימון. מכפלה בין מאפיין מצב ומאפיין מהלך מאפשרת ללמוד העדפה התלויה בהקשר.

לדוגמה, הוספת `x*z` מאפשרת לייצג `Q=b+w*x+u*z+v*x*z`. המשקולות עדיין לינאריות, אך ההשפעה של x תלויה ב־z. נגזרת ההשפעה היא `dQ/dx=w+v*z`. אין צורך לחשב נגזרת של משחק או של המנוע. הפרש כמו `x-y`, כש־x ו־y כבר בקלט, הוא צירוף לינארי שהמודל כבר יכול לייצג; מכפלה, יחס או סף מותנה עשויים להוסיף יכולת חדשה. [תיעוד PolynomialFeatures](https://scikit-learn.org/stable/modules/generated/sklearn.preprocessing.PolynomialFeatures).

המועמדים הבאים משתמשים ב־264 המאפיינים הקיימים. הם הצעות סבירות מבחינת משמעות המשחק, לא אינטראקציות שהוכח כי הן משפרות ניצחונות:

| שם מוצע | חישוב | משמעות |
|---|---|---|
| נקודות לפי קרבה לניצחון | `action_estimated_vp_gain / (1 + own_points_to_win)` | משנה את עדיפות הניקוד לפי מצב המשחק |
| דחיפות הדרך הארוכה | `action_road_length_gain / (1 + own_road_award_gap)` | תוספת אורך מקבלת הקשר של מרחק לבונוס |
| פתיחת יישוב שניתן לממן | `action_best_new_site_yield * min(after_action_settlement_piece_limited_capacity, 1)` | אתר חדש מועיל יותר אם אפשר לממן יישוב ויש חלק פנוי |
| איכות אתר מול מחסור במשאבים | `action_best_new_site_yield / (1 + after_action_settlement_resource_deficit)` | משקל להרחבה שמתאימה ליד אחרי תשלום הדרך |
| דרך כחלק מתוכנית ממומנת | `action_BUILD_ROAD * own_can_fund_two_roads_and_settlement * own_free_sites_two_roads` | העדפת דרך בהקשר של תקציב ויעד נגיש בשתי דרכים |
| עיר שמשחררת חלק יישוב | `action_BUILD_CITY * (own_SETTLEMENTS_AVAILABLE == 0) * own_free_sites_at_network` | ערך לשדרוג כשחסר חלק יישוב ויש לאן להתרחב |
| החלפה שמשלימה עיר | `action_MARITIME_TRADE * (after_action_city_can_afford - own_city_can_afford)` | מזהה החלפה שמסירה את המחסור האחרון לעיר |
| החלפה שמשלימה יישוב | `action_MARITIME_TRADE * (after_action_settlement_can_afford - own_settlement_can_afford)` | מזהה החלפה שמאפשרת יישוב |
| החלפה שמגדילה תקציב דרכים | `action_MARITIME_TRADE * (after_action_funded_road_capacity - own_funded_road_capacity)` | מבדיל החלפה שמקדמת בנייה מהחלפה בלי תועלת בתקציב |
| סיום תור עם בנייה זמינה | `action_END_TURN * (own_city_can_build_now + own_settlement_can_build_now + own_road_can_build_now)` | מאפשר ללמוד מתי סיום תור מבזבז הזדמנות בנייה |
| סיום תור בסיכון השלכה | `action_END_TURN * own_expected_discard_next_roll` | מתנה את עדיפות סיום התור בסיכון המשאבים הנוכחי |
| סינרגיית חיטה ועפרה | `(W + dW)*(O + dO) - W*O` | ערך לשינוי בייצור המשלים של משאבי עיר, כש־W/O הם own_production ו־dW/dO הם production_delta |
| סינרגיית עץ ולבנים | `(L + dL)*(B + dB) - L*B` | שינוי ביכולת לייצר זוג משאבים משלים לדרכים |
| רווח כמותי של עיר מהחלפה | `action_MARITIME_TRADE * (after_action_city_piece_limited_capacity - own_city_piece_limited_capacity)` | מבחין בין תקציב לעיר אחת או כמה שדרוגים, עם חלקים ויישובים |
| אתר חדש ממומן לפי שלב המשחק | `action_best_new_site_yield * min(after_action_settlement_piece_limited_capacity,1) / (1 + own_points_to_win)` | מתנה התרחבות ממומנת במרחק מהניצחון |
| חסימת ייצור ומשמעות היריב | `robber_enemy_production_blocked * victim_public_vp` | קושר חסימת ייצור לניקוד הציבורי של קורבן השוד; זהו קירוב ולא זיהוי מלא של כל מי שנחסם |

אין טעם להתחיל מכל המכפלות הזוגיות: ל־264 קלטים יש 34,716 זוגות שונים, לפני הקלטים המקוריים והריבועים. ההצעה היא להתחיל ב־8–12 מועמדים מתוך הרשימה, לנרמל את התוספות רק על נתוני אימון ולהשאיר את הרגולריזציה פעילה. קודם יש להסיר מאפיינים קבועים, מכפלות שתמיד אפס בגלל החוקיות, וכפילויות עם המאפיינים הקיימים.

כמה אינטראקציות כבר קיימות בקלט ואין להציגן כתוספות חדשות: `cost_hand_fraction`, `gain_build_deficit` ו־`location_production_balance`. לדוגמה, תפוקת משאב במיקום חלקי `(1 + הייצור הנוכחי של אותו משאב)` כבר כלולה. כמו כן `action_BUILD_CITY * own_city_can_build_now` אינו מועמד שימושי: כאשר עיר היא מועמד חוקי, יכולת הבנייה היא תמיד אמת, ולכן המכפלה משכפלת את סוג המהלך.

הבדיקה הבאה צריכה להשוות באותו תקציב אימון את מודל 264 הקלטים לגרסה עם האינטראקציות, על לוחות חדשים. כך ניתן לבחון את התוספות בלי לערבב אותן עם תקציב אימון גדול יותר. אין להשתמש בניצחונות מבדיקת 200 המשחקים הנוכחית כדי לבחור אינטראקציה ספציפית ואז להציג בדיקה חוזרת באותם לוחות כבדיקה עצמאית.
